## 独立结构

```
src/shared/     实体、物理、权威模拟、协议、角色运动
src/server/     HTTP 游客身份、WebSocket、内存队列/房间、固定步长循环
src/client/     输入、预测/校正、插值、Canvas 绘制、网页入口
tests/          模拟回归、协议与真实 HTTP/WebSocket 对战测试
upstream/       原始社区源码和文档（不参与构建）
docs/           开发、设计、验证说明
ops/            独立 systemd / Nginx 文件
scripts/        发布、回滚及 HTTP 验证
```

## 联网设计

- 浏览器负责本地输入与 Canvas 绘制。Node 服务器使用同一套 120 Hz 模拟；每 2 个物理步采样最新逻辑输入（60 Hz），每 4 个物理步推送快照（30 Hz）。保持上游短挥拍窗口的物理精度。短暂积压时合并按下沿、保留挥拍方向组合，确认到最新序号，不多跑角色物理步，也不逐帧积累后续按键延迟。
- 客户端输入只有序号、方向（-1/0/1）、跳跃/挥拍持有与按下沿，不能提交角色位置、席位、球或比分。服务器按 Cookie 对应游客绑定席位，校验 Origin、协议版本、消息长度、字段与发送速率。
- 本地角色立即执行共享运动和挥拍预测；收到快照后恢复该角色权威状态，重放未确认输入。小幅位置误差平滑校正，大误差及回合切换直接恢复。预测不改变球路、碰撞、分数与结果。
- 对手和球缓冲约两个快照间隔，用服务器 tick 插值；不自行预测击球结果。插值缓冲、RTT 和断线变化供后续双机评估，不承诺延迟数值。
- 随机游客 Cookie 使用 HttpOnly、SameSite=Lax，生产环境 Secure，仅覆盖独立入口。HTTP 初始化创建会话，WebSocket 只接受已存在会话。一个游客只能有一个活动连接，新标签页不能抢占连接。
- 匹配状态保存在内存。队列离线立即移除；比赛断线立即清空双方输入并暂停，保留席位 15 秒以允许相同 Cookie 重连。超时判弃权并释放房间；服务器重启不恢复比赛。
- 失焦/隐藏/关闭页面发送清键，恢复前保持空输入；服务器另设输入超时。主动退出判弃权；自然结束保留结算一小段时间，再释放房间。再次匹配由明确按钮触发。

## 分阶段实施及验收

1. 保存来源，拆分模拟/输入/绘制；原物理、AI 测试与无 DOM 比赛测试通过。
2. 实现游客、队列、房间与权威循环；测试两名游客匹配、同身份重复连接拒绝、外来输入拒绝、断线重连和回收。
3. 实现本地预测、校正与远端插值；增加练习入口，测试预测重放与回合重置。
4. 构建独立前端与后端，准备并发布新入口、独立 systemd 服务和 Nginx snippet。只添加新路径，检查已有入口持续可用。
5. 通过类型检查、必要代码测试、构建、HTTP/WebSocket 脚本验证。不得自动启动浏览器。公网两台电脑的按键手感、画面、触屏与弱网效果列为待人工验收。
