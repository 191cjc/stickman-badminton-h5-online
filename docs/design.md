# Flash 原版双人联机设计

## 来源与迁移边界

当前玩法来自 https://www.4399.com/flash/90302.htm 的《火柴人打羽毛球2》。冻结 SWF SHA-256 为 `cab8a824c54af3a0b9454ef30fcbcabc532931f2a96717239fabd58f57e59912`；完整恢复归档、112 个脚本和 gzip XML 保存在 `reference/flash-90302/`。恢复输出不是作者可编辑工程，未核实开放源码授权，保留原版权和标识，不添加 MIT。

原双人菜单的七个角色全部开放：Joe、Nadia、Harry、Toaster、Pirate、Top Hat、Red。只迁移人类双人玩法并改为联网；AI、闯关、角色解锁、Robot 和无菜单入口的 Timmy 不进入产品。源文件仍完整保留。广告、统计和平台跳转不进入运行路径。

社区可执行物理、AI 和绘图已停止使用；`upstream/` 和 `UPSTREAM.json` 是历史来源。本项目自写的 Cookie、匹配、WebSocket、预测和部署层继续复用。其他三个游戏入口、代码及服务保持独立。

## 模拟和权威

逻辑坐标640×426，地面400，网317.25，人物scale1.25。屏幕尺寸只改变等比绘制。服务器以60Hz固定步长运行，30Hz发送快照；先左角色、右角色、球，再动作回调。成人发球23帧、第7帧释放；Toaster27帧、第8帧释放。servePoint 是原未缩放偏移。Toaster 的本帧接触发生在最终 bob 更新之前，预测使用同一步进顺序。

原 `hitTestPoint(false)` 使用全局轴对齐边界；选择区域使用原轮廓。动画和数字几何从同一冻结 XML 派生，保留独立 clip 时钟和隐藏动作播放，不能改成近似挥拍时间窗口。连按不能取消或重启动作；人类规则没有额外的同侧再触球禁令。

球、碰撞、得分和七分结果全部由服务器决定，下一回合间隔1.5s。浏览器只预测自己的角色，按固定60Hz推进，使用 ack/ackTick 对齐已确认的模拟时间，再重放未确认步进；相位、比分、角色、房间或连接状态切换清历史。远端人物与球按权威 tick 插值，离散动作/角色/接触字段来自真实快照。预测不发射球或音效事件。

## 2026-10-14 首次加载体验

静态HTML球场内先显示独立加载层，CSS转圈动画支持减少动态效果偏好。读取清单阶段是不确定进度，之后显示实际499张SVG完成数、原效果模板和首屏缓存阶段，不用计时器伪造百分比，也不添加固定等待。SVG最多6个并发请求，每个图片和清单/模板请求含正文读取最多15秒；失败取消其他图片任务并提供重新加载按钮。音频异步准备，不阻塞进入。

普通Canvas绘制和输入采样在准备完成前暂停。按当前场景选出首屏网/分数/人物/背景等帧，使用正常绘制的DPR/角色缩放档逐项预热原滤镜缓存；每项之前和最后让出绘制机会，用单像素读取使延迟栅格工作在加载层期间完成。只准备当前帧，不遍历所有动画，原64/32MiB预算不变。状态或尺寸变化至多尝试准备3次；重复空闲/暂停消息不清除同一已准备缓存。WS仍接收真实状态，原Cookie房间恢复时完成加载直接显示当前比赛，不重置为菜单；揭幕前清键，再按真实场景恢复采样。失败保持操作门槛和可用重试。单个SVG同步栅格化、后续新帧和后台浏览器调度仍有局限，加载动画不保证完全无停顿。

## 2026-10-14 平滑优化

保持协议3、服务器60Hz模拟与30Hz快照，未更换联网框架。客户端改用单调推进的权威呈现时间轴：32快照与60个抖动样本，目标缓冲在4..12tick内自适应（约66.7..200ms，配置范围，不是实测动作延迟），时钟误差有界校正，呈现速率0.85..1.15。连续回合不回跳，旧包/重复包忽略，比分/相位/角色/房间/状态变化重置；断档只停在最新真实状态，不外推球的接触与得分。

输入由单页60Hz计时器采样，RAF只负责绘制与呈现。计时器请求向上取整，迟到时跳过遗漏周期并保留原相位；下一截止时间不足约4.17ms时再跳一周期。每次至多发送一帧，避免集中补发，也避免重新等待完整周期的额外损失。同步peek→send→commit：本地socket接受发送后才消费边沿、递增序号并预测；断连/64KiB背压/发送异常保留边沿。失焦、隐藏、断线、退出、结果与房间变化清键并停采样，恢复时从新截止时间开始。浏览器主线程阻塞仍会阻塞计时器。

原SVG和滤镜首次按实际Canvas变换（含DPR/镜像/旋转）栅格化，并通过半倍频程0.25..4缩放档复用。普通缓存256项/64MiB，彩屑独立768项/32MiB，单项24MiB、单边4096；超大图降低缓存密度，分配失败回退原图。保留原点、滤镜溢出、图层和目标尺寸；场景/角色/房间切换释放画布及旧Blob。上述字节为RGBA缓存估算，包含的96MiB上限不等于浏览器总内存。

显式`?debug=1`才创建本地只读`window.badmintonDiagnostics.snapshot()`，每个数值序列最多240个样本，记录帧间隔/执行/长任务、快照间隔/字节、RTT、校正、未确认输入年龄、缓存和时间轴统计。默认页面不启用，不收集身份或上传数据。使用及证据见部署和验证文档。

## 2026-10-15 击球时序优化

本地预测与输入发送解耦：发送成功的操作登记到命令历史，使用上次接受的 held 状态按固定60Hz推进自己的角色。advance 使用单调时间，先推进旧操作，再接受新操作；发送、收包和RAF共享同一个累积器，不按包数加速。每次最多补6步/100ms，最多保留120步、240条命令和2秒历史。挥拍/跳跃边沿按服务器相同规则合并后消费一次，仍遵守原版动作锁。

快照新增服务器拥有的 `ackTick`：当前 ack 的命令首次完成模拟的房间 tick；继续 held 时保持不变，release、输入超时、断线/重连清键和丢弃操作时为 null。seq 是操作标识，不能当模拟帧号。有效锚点用该命令本地首次生效步加 `snapshot.tick - ackTick` 对齐已确认 held 时间，不能据此删除 seq>ack 的操作。缺失/合包掉的锚点、时间映射越过未确认操作时，只以新权威人物建一次有界近似，再消费待确认操作并继续固定步。同 ack 的快照不能反复重置人物和挥拍；2秒过期后暂停该代预测，等待 ack 前进或真正生命周期重置，不能周期性复活旧边沿。这是非对称网络停顿时的近似，并非完整回滚。

Input 在逻辑操作实际变化后通知同一个发送计时器，合并提前发送和普通60Hz周期。尝试间隔至少8.33ms，理论上约120Hz，低于服务器180消息/s；提前发送后重排周期，迟到不补发旧输入。发送失败仍保留边沿和序号。球的最低插值缓冲从4tick改为2tick，最大12tick、自适应抖动、单调游标和断档hold规则保持；约33ms只是最低缓冲配置，不是实测总延迟。特效和音频继续使用同一权威呈现时间。

不修改原版球路、球拍范围、动作时间、属性和素材，不预测本地球或暂定得分，也不混用历史球位与当前球拍补判。完整服务器回滚另行评估。验证证据与局限见 [validation.md](validation.md)。

## 2026-10-16 持续运行优化

同内容的原SVG按清单SHA-256和实际缓存尺寸共享栅格，预热和正常绘图使用相同身份；每帧仍保留自己的原点和目标尺寸，原滤镜与64/32MiB缓存上限保持。降低密度时只释放栅格画布，保留正在运行的闪光、球尾、烟雾、彩屑及音频。

独立RenderQuality在普通页面也运行。初始使用最高DPR2；持续过载时从世界像素密度上限 `[4, 2.8, 2, 1.4, 1]` 中选择实际有效的下一低档。有效DPR为原生上限与“档位/窗口世界缩放”的较小值，大窗口可以低于DPR1。只调整Canvas内部像素数，CSS窗口、640×426世界和输入坐标不变。至少2秒且至少4个样本才完成观察，超过25ms的慢帧占比达到50%才降一档；场景/焦点/尺寸变化留1秒宽限，降档后冷却6秒。只观察已加载、可见、聚焦的稳定对战或自然结果，排除排队、加载和暂停重连；断线回调重置观察，已有自然结果仍可继续观察本地动画。页内只降不升、再次匹配保留、刷新重新评估；高倍率细节会变柔和，阈值不是FPS保证。

连续呈现的采样停顿超过250ms时，插值时钟以最新真实快照及其收到时刻重新锚定，一次向前恢复到当前目标缓冲附近，受已收到的同段权威状态约束；不回跳、不越过最新状态、不预测球。普通采样仍采用原单调平滑规则，比分/角色/状态等边界即时重置。恢复会跳过停顿期间已过时的画面，不能重建冻结时未看到的过程。

输入最小间隔按尝试开始时刻计算，同步回调耗时计入间隔，避免完成后又额外保留一次间隔而跳过可用周期；仍由一个计时器每次至多尝试一帧，失败保留边沿。特效静音标志改为随待处理事件拥有，队列丢弃也一并回收；快进时只播放距最终呈现目标6tick内的新鲜声音，不补播过期音效。所有改造仅在客户端，协议4、服务端模拟和冻结素材不变。

## 协议、游客与输入

协议5，WebSocket `badminton-v5`，状态 `flash-90302-v3`。v1/v2/v3/v4在绑定 socket/游客/席位之前发送刷新提示并拒绝；前后端同时发布。客户端只发送 `{type:"queue", character:<七角色ID>, shuttleSpeed:<四档数值>}` 或严格逻辑操作，不能自报房间、席位、坐标、球、得分或结果。

角色和档位在排队和房间内固定，重复相同配置 queue 幂等，改变任一项需取消重排；双方可相同角色。签名 Cookie、Origin、单连接和枚举/字段/速率检查保护席位。双方统一 A/D/方向键移动、K/↑跳跃、J/↓/空格击球，W/S为高低位修饰；M静音，Esc发送已有leave。

输入积压合并为最新 held、跳跃边沿和最近击球边沿及其 swing模式和 hit-time jump，保留 `hitJump` 合包保护，删除无用途的内部 `hitMove`。一个权威步完成后才确认输入，不通过积压加速模拟。

失焦/隐藏/pagehide发送release，750ms无输入清键。断线清双方输入并暂停，原Cookie保留席位15s；恢复后按原角色及ack继续，过期判弃权并回收。队列120s、结果30s、单场20分钟；重启清空内存比赛，Cookie密钥跨发布保持不变。

## 呈现事件与资源生命周期

服务器按真实动作生成带单调ID、tick、位置和独立随机seed的效果事件，记录闪光/声音与连续尾迹、烟雾的发射点。journal最多128组、保留30tick；不传每个活粒子的坐标。cosmetic RNG独立，不改变球或计分。

客户端按插值的权威时间消费事件、去重并快进过期效果；重连建立cursor基线跳过历史声音，新房间/退出清效果。粒子使用独立60Hz呈现步进，避免RAF频率改变密度和寿命。自然结果冻结权威模拟，结果人物使用终局状态的深拷贝，以空输入和pointActive:false复用共享人物步进，完成空中落地、剩余动作及Toaster的bob/烟雾；单独呈现时钟继续彩屑，直到离开结果。这些副本不碰球、计分或生成权威事件，资源有上限及回收。

绘制顺序为场景、网、分数/标记、烟雾、人物、星尾、球，再按创建顺序的前景闪光/介绍/结果/彩屑。SVG滤镜保留溢出padding和原点补偿。原比赛HUD的KONGREGATE标识保留默认图层，移除其跳转行为；场内按钮避开标识。彩屑颜色通过有界SVG Blob图片缓存生成，CSP仅为本项目允许 `img-src 'self' blob:`；清场撤销URL，过期加载不能重新污染场景。

声音在用户手势后启用，支持重叠短音、音乐、场内静音/M和有界清理。音乐使用独立gain按源60Hz callback的1/(2*30)增量淡入，不能把源fade参数2直接宣称为原生实测两秒。miss只发whoosh，普通成功发球/击球有birdiehit，Toaster发球为whoosh+spark+pop且无birdiehit；每分ding一次、自然胜利cheer一次。不添加未调用的SmallSpark、墙网撞击声或战役声效。

## 验证、发布与限制

先做冻结来源、几何/动画、七角色动作、球路/计分、事件/音频、预测、严格协议及真实HTTP/WS比赛检查，再进行已授权的隔离Chromium与未修改SWF的Ruffle对照。逐项实际记录见 [validation.md](validation.md)。迁移回放和兼容运行不能证明原生Flash逐像素或随机序列完全一致；独立cosmetic RNG保留原分布而不保留全局Math.random耦合。

Nginx提供静态文件，systemd管理独立Node服务，同源WS代理。release一起切换前后端并保留上一版，保持Cookie密钥；回滚也同时切回两端并刷新页面。其他游戏资源不操作。物理双机、触屏、其他浏览器与弱网手感仍需外部验收，不承诺延迟。启动、发布、日志和回滚见 [deployment.md](deployment.md)。

## 2026-10-22 球速场次与手动挥拍

协议统一升级为5 / `badminton-v5`，状态版本为 `flash-90302-v3`。共享 `match-settings.ts` 定义唯一数值档位 `[1, 1.25, 1.5, 2]`。queue 精确包含 character 和 shuttleSpeed，queued/matched 回显；模拟只读配置和快照携带本场档位。单个有界 FIFO 队列按档找最早成对游客，同档保持先后次序，孤立档不阻塞其它档，不跨档配对。取消、断线、超时和成功配对均清除待匹配配置。菜单保留本页下一场选择，HUD和结果保留服务器确认的本场速度，重连恢复原房间配置。

1x保留原始运算路径。高速档每个真实60Hz帧只将球推进两子步，每步为 `dt * shuttleSpeed / 2`；人物、动画、发球释放和回合等待只更新一次。第二子步前复用本帧姿态及Toaster pre-bob接触原点再检查球拍，地面得分立即关闭接触。球速字段仍为原生单位，不再乘倍率；落点预估采用对应子步dt。每真实tick最多一次原版球尾发射机会，效果时钟和上限不变。分数倍率的离散积分与原1x存在少量轨迹差异，不代表整局时间加速或保证高速接触无离散误差。

键盘六项动作默认移动A/D、跳K、挥拍J、高位修饰W、低位修饰S。修饰在聚合挥拍false→true时捕获：仅高位为overhead、仅低位为underhand、均按或均未按为auto。发球优先，强制模式只绕过自动选型，不绕过原版恢复/接触锁。输入新增必需swing字段；hitPressed为false时只能auto。pending hit按keyboard/pointer/gamepad三类保留最新未发送模式，发送成功才消费；清手柄仅删除其贡献。服务器和预测均从最新hit帧取模式与hitJump，后续held包不能覆盖。模拟小dt尚未消费时也保留该负载。镜像只翻水平，不交换高低位。

本地偏好升级为 `fiso-online:controls:v2` / version2。仅v2不存在时严格迁移v1；旧四项集合等于默认布局则升级所有新默认并保留手柄开关，真正自定义/空绑定保留，W/S有冲突则相应修饰为空。无效v2回退新默认，不复活旧配置；v1不删除。手柄/触屏维持原四动作，键盘修饰可影响它们的新挥拍沿。球插值同时检查rallyHits，避免同侧再次命中被平滑成错误球路；每次击球不重置整个插值时钟。配置或schema变化则清预测和插值旧历史。

旧v1–v4连接仅获protocol_mismatch及1008关闭，在绑定游客/席位之前处理。输入60Hz、权威60Hz、快照30Hz、15秒重连和30秒结果规则保持。
