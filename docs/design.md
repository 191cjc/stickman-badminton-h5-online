# Flash 原版双人联机设计

## 来源与迁移边界

当前玩法来自 https://www.4399.com/flash/90302.htm 的《火柴人打羽毛球2》。冻结 SWF SHA-256 为 `cab8a824c54af3a0b9454ef30fcbcabc532931f2a96717239fabd58f57e59912`；完整恢复归档、112 个脚本和 gzip XML 保存在 `reference/flash-90302/`。恢复输出不是作者可编辑工程，未核实开放源码授权，保留原版权和标识，不添加 MIT。

原双人菜单的七个角色全部开放：Joe、Nadia、Harry、Toaster、Pirate、Top Hat、Red。只迁移人类双人玩法并改为联网；AI、闯关、角色解锁、Robot 和无菜单入口的 Timmy 不进入产品。源文件仍完整保留。广告、统计和平台跳转不进入运行路径。

社区可执行物理、AI 和绘图已停止使用；`upstream/` 和 `UPSTREAM.json` 是历史来源。本项目自写的 Cookie、匹配、WebSocket、预测和部署层继续复用。其他三个游戏入口、代码及服务保持独立。

## 模拟和权威

逻辑坐标640×426，地面400，网317.25，人物scale1.25。屏幕尺寸只改变等比绘制。服务器以60Hz固定步长运行，30Hz发送快照；先左角色、右角色、球，再动作回调。成人发球23帧、第7帧释放；Toaster27帧、第8帧释放。servePoint 是原未缩放偏移。Toaster 的本帧接触发生在最终 bob 更新之前，预测使用同一步进顺序。

原 `hitTestPoint(false)` 使用全局轴对齐边界；选择区域使用原轮廓。动画和数字几何从同一冻结 XML 派生，保留独立 clip 时钟和隐藏动作播放，不能改成近似挥拍时间窗口。连按不能取消或重启动作；人类规则没有额外的同侧再触球禁令。

球、碰撞、得分和七分结果全部由服务器决定，下一回合间隔1.5s。浏览器只预测自己的角色，收到 ack 后恢复权威角色并重放未确认输入；相位、比分、角色、房间或连接状态切换清历史。远端人物与球按权威 tick 插值，离散动作/角色/接触字段来自真实快照。预测不发射球或音效事件。

## 2026-10-14 首次加载体验

静态HTML球场内先显示独立加载层，CSS转圈动画支持减少动态效果偏好。读取清单阶段是不确定进度，之后显示实际499张SVG完成数、原效果模板和首屏缓存阶段，不用计时器伪造百分比，也不添加固定等待。SVG最多6个并发请求，每个图片和清单/模板请求含正文读取最多15秒；失败取消其他图片任务并提供重新加载按钮。音频异步准备，不阻塞进入。

普通Canvas绘制和输入采样在准备完成前暂停。按当前场景选出首屏网/分数/人物/背景等帧，使用正常绘制的DPR/角色缩放档逐项预热原滤镜缓存；每项之前和最后让出绘制机会，用单像素读取使延迟栅格工作在加载层期间完成。只准备当前帧，不遍历所有动画，原64/32MiB预算不变。状态或尺寸变化至多尝试准备3次；重复空闲/暂停消息不清除同一已准备缓存。WS仍接收真实状态，原Cookie房间恢复时完成加载直接显示当前比赛，不重置为菜单；揭幕前清键，再按真实场景恢复采样。失败保持操作门槛和可用重试。单个SVG同步栅格化、后续新帧和后台浏览器调度仍有局限，加载动画不保证完全无停顿。

## 2026-10-14 平滑优化

保持协议3、服务器60Hz模拟与30Hz快照，未更换联网框架。客户端改用单调推进的权威呈现时间轴：32快照与60个抖动样本，目标缓冲在4..12tick内自适应（约66.7..200ms，配置范围，不是实测动作延迟），时钟误差有界校正，呈现速率0.85..1.15。连续回合不回跳，旧包/重复包忽略，比分/相位/角色/房间/状态变化重置；断档只停在最新真实状态，不外推球的接触与得分。

输入由单页60Hz计时器采样，RAF只负责绘制与呈现。计时器请求向上取整，迟到时跳过遗漏周期并保留原相位；下一截止时间不足约4.17ms时再跳一周期。每次至多发送一帧，避免集中补发，也避免重新等待完整周期的额外损失。同步peek→send→commit：本地socket接受发送后才消费边沿、递增序号并预测；断连/64KiB背压/发送异常保留边沿。失焦、隐藏、断线、退出、结果与房间变化清键并停采样，恢复时从新截止时间开始。浏览器主线程阻塞仍会阻塞计时器。

原SVG和滤镜首次按实际Canvas变换（含DPR/镜像/旋转）栅格化，并通过半倍频程0.25..4缩放档复用。普通缓存256项/64MiB，彩屑独立768项/32MiB，单项24MiB、单边4096；超大图降低缓存密度，分配失败回退原图。保留原点、滤镜溢出、图层和目标尺寸；场景/角色/房间切换释放画布及旧Blob。上述字节为RGBA缓存估算，包含的96MiB上限不等于浏览器总内存。

显式`?debug=1`才创建本地只读`window.badmintonDiagnostics.snapshot()`，每个数值序列最多240个样本，记录帧间隔/执行/长任务、快照间隔/字节、RTT、校正、未确认输入年龄、缓存和时间轴统计。默认页面不启用，不收集身份或上传数据。使用及证据见部署和验证文档。

## 协议、游客与输入

协议3，WebSocket `badminton-v3`，状态 `flash-90302-v2`。v1/v2在绑定 socket/游客/席位之前发送刷新提示并拒绝；前后端同时发布。客户端只发送 `{type:"queue", character:<七角色ID>}` 或严格逻辑操作，不能自报房间、席位、坐标、球、得分或结果。

选择在排队和房间内固定，重复同角色 queue 幂等，改角需取消重排；双方可相同角色。签名 Cookie、Origin、单连接和枚举/字段/速率检查保护席位。双方统一 A/D/方向键移动、W/↑跳跃、S/↓/空格击球；M静音，Esc发送已有leave。

输入积压合并为最新 held、跳跃边沿和最近击球边沿及其 hit-time jump，保留 `hitJump` 合包保护，删除无用途的内部 `hitMove`。一个权威步完成后才确认输入，不通过积压加速模拟。

失焦/隐藏/pagehide发送release，750ms无输入清键。断线清双方输入并暂停，原Cookie保留席位15s；恢复后按原角色及ack继续，过期判弃权并回收。队列120s、结果30s、单场20分钟；重启清空内存比赛，Cookie密钥跨发布保持不变。

## 呈现事件与资源生命周期

服务器按真实动作生成带单调ID、tick、位置和独立随机seed的效果事件，记录闪光/声音与连续尾迹、烟雾的发射点。journal最多128组、保留30tick；不传每个活粒子的坐标。cosmetic RNG独立，不改变球或计分。

客户端按插值的权威时间消费事件、去重并快进过期效果；重连建立cursor基线跳过历史声音，新房间/退出清效果。粒子使用独立60Hz呈现步进，避免RAF频率改变密度和寿命。自然结果冻结权威模拟，结果人物使用终局状态的深拷贝，以空输入和pointActive:false复用共享人物步进，完成空中落地、剩余动作及Toaster的bob/烟雾；单独呈现时钟继续彩屑，直到离开结果。这些副本不碰球、计分或生成权威事件，资源有上限及回收。

绘制顺序为场景、网、分数/标记、烟雾、人物、星尾、球，再按创建顺序的前景闪光/介绍/结果/彩屑。SVG滤镜保留溢出padding和原点补偿。原比赛HUD的KONGREGATE标识保留默认图层，移除其跳转行为；场内按钮避开标识。彩屑颜色通过有界SVG Blob图片缓存生成，CSP仅为本项目允许 `img-src 'self' blob:`；清场撤销URL，过期加载不能重新污染场景。

声音在用户手势后启用，支持重叠短音、音乐、场内静音/M和有界清理。音乐使用独立gain按源60Hz callback的1/(2*30)增量淡入，不能把源fade参数2直接宣称为原生实测两秒。miss只发whoosh，普通成功发球/击球有birdiehit，Toaster发球为whoosh+spark+pop且无birdiehit；每分ding一次、自然胜利cheer一次。不添加未调用的SmallSpark、墙网撞击声或战役声效。

## 验证、发布与限制

先做冻结来源、几何/动画、七角色动作、球路/计分、事件/音频、预测、严格协议及真实HTTP/WS比赛检查，再进行已授权的隔离Chromium与未修改SWF的Ruffle对照。逐项实际记录见 [validation.md](validation.md)。迁移回放和兼容运行不能证明原生Flash逐像素或随机序列完全一致；独立cosmetic RNG保留原分布而不保留全局Math.random耦合。

Nginx提供静态文件，systemd管理独立Node服务，同源WS代理。release一起切换前后端并保留上一版，保持Cookie密钥；回滚也同时切回两端并刷新页面。其他游戏资源不操作。物理双机、触屏、其他浏览器与弱网手感仍需外部验收，不承诺延迟。启动、发布、日志和回滚见 [deployment.md](deployment.md)。
