# Flash 原版联机迁移设计（已批准）

## 架构

基线是 Flash 90302 的未修改 SWF 和恢复 ActionScript，依据见 `research/flash-original.md`。建立独立的共享 TypeScript 原版内核，替换社区模拟；浏览器 Canvas 本地绘制，Node 负责球路、碰撞、比分与结果。游客/匹配/席位/回收/部署从本项目复用。云游戏及旧原版 H5 只读。

## 拟用目录

- `reference/flash-90302/`：来源、冻结恢复代码、语义映射，非公网。
- `tools/flash-assets/`：从 SWF XML 提取时间轴、碰撞、渲染数据。
- `src/shared/classic/`：原版状态、输入、玩家、球、动画、AI、计分。
- `src/client/`：保留界面/输入/网络，接新渲染和预测。
- `src/server/`：保留匹配服务，接新权威模拟。
- `public/classic/`：经验证的画面资源，不包含恢复脚本和整套原发布程序。
- `tests/classic/`：原版证据、回放、碰撞和完整比赛。

大型 Java/JPEXS 工具留在 Git 忽略研究目录。现有 upstream/ 和 UPSTREAM.json 保留历史记录；正式玩法不继续导入社区模拟。首版普通角色范围已获批准。

## 原版模拟与画面

采用 SWF 逻辑坐标 640×426，界面等比放大。将恢复方法映射为正常标识符，保留输入、角色、球与计分推进顺序。getTimer/setTimeout 换成显式模拟时间；AI 随机源可记录、重放、暂停。

提取所选角色和动作的实例层级、帧标签、每帧变换、可见性及碰撞形状。需要处理嵌套时间轴；静态整图 SVG 不等于运行中只显示一种挥拍的角色。服务端按数值变换裁决，客户端按相同动作帧绘制，发球第 7 帧及动作恢复事件不依赖浏览器墙钟。

首先评估 60-Hz 模拟/输入、30-Hz 快照，以原版 60-fps 时间轴为依据，通过原版对照决定最终频率。不能直接保留社区 120-Hz 双子步并认定等效。原版球网扫掠、反弹、侧墙与单次计分分别迁移；任何行为修正明确记录。

原 AI 有最后击球者检查，应保留。原玩家判定未显示同样的拒绝条件，重复触球需运行对照，不提前保证原版绝无此问题。

## 联机与即时反馈

新状态结构包括动作帧、跳跃/挥拍锁存与模拟计时；提升协议版本处理旧页面。服务端只接受已有范围内逻辑操作，不能接收玩家自报的席位、位置或分数。

共享角色推进用于本地预测和服务器模拟。移动、跳跃和明确挥拍操作在本地响应，权威快照确认后重放未确认输入；在线球及比分不由本地决定。远端角色与球使用快照插值。输入合包、边沿、ack/tick 含义和频率共同复核；移除旧双子步假设。练习使用同一新内核的本地 AI。

## 验证与运行边界

先验证内核及动画，再接本地两游客真实 HTTP/WS 和 Canvas，最后独立发布。原 Flash 运行对照优先评估隔离 AS3 兼容运行器；不足时报告证据缺口，不以 H5 转换版或恢复代码自身的回放冒充 Flash 实机行为。

检查两侧发球、重复挥拍、AI 接球、网顶/网侧/侧墙/落地、单次计分、七分结果、预测校正、输入合包和房间回收。测试依据独立记录，不能复制移植方法当作对照。

目前只完成静态恢复和样本导出。真实手感、运行事件顺序、完整动画碰撞及网络体验待实施验证。来源记录保留未确认开放许可的事实，不添加 MIT。

保持独立 Nginx/systemd 入口，迁移验收前不切当前公网版本。发布时处理协议版本及旧连接，保留现行 release 回滚；验证原版验证、社区试玩及云游戏入口隔离。
