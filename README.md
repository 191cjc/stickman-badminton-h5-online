# 火柴人羽毛球 H5 在线对战

独立项目目录 `/home/ubuntu/stickman-badminton-h5-online/`，公网入口 https://www.firesoul.cn/badminton-h5-online/ 。本地开发版采用 PixiJS 8.22.0 WebGL 绘制，Node.js 服务器权威模拟，通过同源 WebSocket 联机；本次渲染改造尚未发布生产。

在游戏内选择角色、球速场次并点击开始匹配，两名同档游客进入同一房间，无需账号、密码或昵称。球速可选 **1x / 1.25x / 1.5x / 2x**，只加快羽毛球，人物移动、跳跃、挥拍和回合等待保持原节奏；不同档位独立匹配。排队和比赛期间锁定，取消或结算后可换档再次匹配。先到 7 分获胜。匹配、选角、取消、结束、静音和设置控件位于游戏区域内，也提供触屏操作。

默认 A/D 或 ←/→ 移动，**K/↑ 跳跃，J/↓/空格挥拍与发球**。单按挥拍键沿用自动选型；按住 **W 再按 J 为高位挥拍，S 再按 J 为低位挑球**。W/S 单独按不跳跃也不挥拍，两者同按为自动。动作开始后改变修饰不换动作，仍受原版恢复和命中范围限制；发球保持专用发球动作。组合随设置中的动作绑定变化。

“设置”中可开启“自己始终显示在左侧”（默认关闭），每位玩家独立选择并记住在当前浏览器。左右键始终按画面方向移动；比赛中也能切换，打开设置会清除按键并暂时停止自己的操作，比赛继续，点击“完成”或按 Esc 恢复操作。比分、角色介绍与原版效果随视角调整，服务器的实际席位和判定保持不变。浏览器禁用存储时，本页仍可切换。

“键盘按键”支持向左、向右、跳跃、挥拍／发球、高位挥拍修饰、低位挑球修饰六项，各最多三个按键。点击现有按键移除，点击“添加”后按新键；冲突或不支持的键会提示，配置保留。允许暂时未设置，可“恢复默认按键”。M 保留静音，Esc 先取消捕获、再关闭设置；Tab 保持原生焦点导航，浏览器组合快捷键不用于比赛。按键和手柄启用选项仅保存在当前浏览器；存储不可用时本页设置仍生效。触屏按钮保持固定动作。旧默认布局自动升级为 J/K/W/S；自定义布局和空绑定保留，若 W/S 已被占用，对应新修饰显示“未设置”，可自行添加。原 v1 设置保留供旧版本回滚，新编辑写入 v2。

手柄默认启用，仅接受浏览器报告的标准布局，自动选择一个设备并在连接期间保持。方向键／左摇杆左右移动；右侧按钮组底部按钮跳跃、左侧按钮挥拍／发球（常见 Xbox A／X、PlayStation ×／□）。连接后可能需要先在本页按一下手柄按钮，再在设置中点击“检测手柄”。关闭设置、失焦恢复、重连和再次匹配后先松开全部比赛按钮、摇杆回中，再重新操作；拔除或关闭手柄不会清除键盘／触屏的正常操作。手柄不操作匹配／设置菜单，首版没有手柄改键、非标准布局映射、震动或多手柄同时控制。使用原生按钮／设置时不接受比赛操作，点击球场或触屏按钮可恢复游戏焦点。

代码与合成 Gamepad API 检查的结果见[验证记录](docs/validation.md)。合成输入不能证明实体手柄兼容性；实际 USB／蓝牙设备、浏览器／系统映射及真人双机手感仍需实机验收，不承诺所有品牌型号可用。

首次打开会显示实际图片解码和纹理准备进度，完成后开放选角与匹配。原 SVG 的复杂滤镜已在构建阶段烘焙，运行时按场景、角色和动作族加载透明无损 PNG 图集；新角色组合准备期间继续接收比赛状态，完成后恢复操作。加载失败可重新加载，也可结束当前比赛。需要浏览器支持 WebGL；尺寸变化和画质调整只改变内部绘制密度。同条件性能、画面对照及设备范围见 [Pixi 迁移报告](docs/pixi-migration.md)。

## 当前玩法来源

当前内核迁移自 4399 Flash《火柴人打羽毛球2》：https://www.4399.com/flash/90302.htm 。已保存原发布 SWF、112 个恢复脚本、完整时间轴/形状 XML 及完整恢复归档。共享 TypeScript 迁移原版人类双人动作、球路、碰撞和计分，PixiJS 绘制原版派生素材，恢复击球闪光、星形球尾、Toaster 烟雾、自然胜利彩屑及原音效。

原双人模式的七个角色全部直接开放：Average Joe、Naughty Nadia、Hairy Harry、Flying Toaster、Pirate Pete、Top Hat Sam、The Red Dude；双方可选相同角色。正式产品只保留在线双人，不提供 AI 对练、闯关、解锁和存档。原始单人代码仍完整归档。

[GAME_SOURCE.json](GAME_SOURCE.json) 记录当前来源与范围，[reference/flash-90302/](reference/flash-90302/) 保存未修改 SWF、恢复脚本、压缩 XML 和逐文件哈希。这是编译文件的恢复输出，不是作者原始开放源码工程。保留原作 Effing Games 等版权标识，未核实开放源码授权，不添加或宣称 MIT。

此前社区仓库 https://github.com/LoveSeele-max/stickman_badminton_h5 、提交 `1a8799e65a39f7dafab2075c9297d8e4965f1ecb` 已停止用于正式玩法。`upstream/` 和 `UPSTREAM.json` 保留历史副本及版本核验，不参与生产构建；该提交也未发现许可证声明。已有游客联机与部署能力从本项目保留。

## 本地开发

需要 Node.js 24+。依赖与 lockfile 独立，`.npmrc` 仅为本项目设置 npm 官方 registry。

```bash
cd /home/ubuntu/stickman-badminton-h5-online
npm ci
npm run dev
# http://127.0.0.1:5184/badminton-h5-online/
npm run typecheck
npm run lint
npm test
npm run build
npm start
```

仓库包含生成后的透明 PNG 图集，普通开发与构建无需启动烘焙浏览器；`npm run build` 会先核验素材来源、页面哈希和图集尺寸。修改派生 SVG 或完整重提取后，执行：

```bash
npx playwright install chromium
npm run assets:atlas
npm run assets:verify
# 在相同工具环境独立重建并逐文件比较：
npm run assets:atlas -- --check
```

详细构建约定见 [素材工具说明](tools/flash-assets/README.md)。渲染设计与实测证据分别见 [设计文档](docs/design.md)和[验证记录](docs/validation.md)。

前端端口 5184，后端只绑定 127.0.0.1:8794；Vite 代理本项目 API/WS。生产服务运行期间，本地验证应使用其他端口及独立代理，避免进入线上队列。两名游客需不同浏览器配置或独立 Cookie；同一浏览器多个标签页属于同一游客，只允许一个活动连接。

测试覆盖原版来源/七角色几何、动作事件、球路/碰撞、计分、预测、效果/音频生命周期、协议、身份校验与真实 HTTP/WebSocket 七分比赛。常规命令不会自动启动浏览器。素材重建方法见 [tools/flash-assets/README.md](tools/flash-assets/README.md)。

## 结构与网络

`src/shared/classic/` 是无 DOM 的原版模拟及动作数据，`src/shared/` 提供协议和适配；`src/server/` 负责游客 Cookie、内存匹配、房间和权威循环；`src/client/` 负责输入、预测/校正、插值与 PixiJS；`public/classic/` 保存派生 SVG、原音频和来源清单，`public/classic-atlas/` 保存可重复构建的图集。`reference/` 和 `upstream/` 不进入公网静态目录。

服务器模拟与本地角色预测按固定 60 Hz 推进，快照为 30 Hz，沿用原版 60 fps 动作时间轴。输入正常按 60 Hz 发送，逻辑变化提前发送，两次尝试至少间隔约 8.33 ms；发送次数不决定移动速度。积压输入合并为最新持有状态和按下沿，不额外运行模拟帧。客户端只预测自己的角色，以服务器 ack/ackTick 对齐已确认模拟时间，再重放尚未确认的步进；锚点不完整时进入有界近似，长时间未确认则暂停预测。羽毛球、比分和结果由服务器裁决。对手和球按单调自适应时间轴插值，健康网络目标最低缓冲为一个快照间隔（约 33 ms 的配置值），断档保持最新权威状态；发送成功后才消费边沿。原 SVG 滤镜在构建阶段烘焙，效果使用去重事件和独立呈现时钟。Pixi 不运行第二套动画循环；纹理按本场角色组合有界持有。RTT 不等于按键动作延迟，实体双机与弱网手感须另行验收。

协议为 v5（`badminton-v5`、`flash-90302-v3`），旧页面须刷新。角色和球速选择在排队和房间内锁定；断线清键并暂停，原 Cookie 的席位保留 15 秒。重连建立效果事件基线，不重播旧声音；服务重启会清空内存比赛。

设计：[docs/design.md](docs/design.md)。发布、日志和回滚：[docs/deployment.md](docs/deployment.md)。实际验证与外部双机验收：[docs/validation.md](docs/validation.md)。

卡顿诊断可显式使用`?debug=1`和`window.badmintonDiagnostics.snapshot()`；默认关闭且不上报。实际测量与限制见[验证记录](docs/validation.md)，诊断字段见[部署文档](docs/deployment.md)。
